# Бот закупок и оплат — пошаговое внедрение

Что делает бот: сотрудник подаёт заявку мастером в личке боту (с обязательным фото счёта), бот публикует её в общий чат единым форматом. Директор ставит реакцию 🟢/✖, бухгалтер — ✅. Бот проверяет, что реакцию поставил именно тот человек, записывает точное время в базу, шлёт сотруднику личное уведомление о статусе, и по кнопке показывает отчёт по каждому из 4 секторов.

## 1. Создать бота

1. Откройте в Телеграме `@BotFather`.
2. Команда `/newbot`, придумайте имя и username.
3. BotFather пришлёт токен вида `123456:AAH...` — это `BOT_TOKEN`. Никому не показывайте.

## 2. Добавить бота в группу закупок

1. Добавьте бота участником в вашу группу «Закупки».
2. Сделайте его администратором группы (нужно как минимум право «Закреплять сообщения» — бот использует это для напоминаний об окне).
3. Управление группой → Разрешения → Реакции — включите реакции и оставьте (или ограничьте) набор так, чтобы в нём точно были 🟢, ✖ и ✅.

## 3. Узнать ID группы и людей

1. Попросите директора и бухгалтера один раз написать боту `/start` в личных сообщениях — без этого бот не сможет им ничего написать (так устроен Телеграм).
2. Кто-нибудь должен написать любое сообщение в саму группу.
3. Установите зависимости (см. шаг 4) и запустите:
   ```
   python get_ids.py
   ```
4. В выводе найдите строку с `chat.type=supergroup` — это `GROUP_CHAT_ID` (число со знаком минус, например `-1001234567890`). Найдите строки с именами директора и бухгалтера — их `user.id` это `DIRECTOR_ID` и `ACCOUNTANT_ID`.

## 4. Установить зависимости

Нужен Python 3.10 или новее.

```
cd telegram_bot
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 5. Настроить .env

```
cp .env.example .env
```
Откройте `.env` и заполните `BOT_TOKEN`, `GROUP_CHAT_ID`, `DIRECTOR_ID`, `ACCOUNTANT_ID` значениями из шагов 1 и 3.

## 6. Запустить

```
python main.py
```
В консоли должно появиться `Бот запущен`. Пока это окно открыто — бот работает.

## 7. Проверить сценарий целиком

1. Любой сотрудник пишет боту в личку `/new`, выбирает сектор, вводит поставщика, сумму, наряд, прикрепляет фото — бот публикует заявку в группу.
2. Директор ставит 🟢 на это сообщение в группе — сотрудник должен в течение секунд получить личное сообщение «Заявка ... одобрена».
3. Бухгалтер ставит ✅ — сотрудник получает «оплачена, можно ехать за материалом».
4. В группе `/report` — нажмите сектор, должна прийти сводка с суммами.
5. Дождитесь времени из `WINDOW_SUBMIT_OPEN` в `config.py` — бот должен сам написать и закрепить сообщение об открытии окна.

Если что-то не пришло — проверьте, что бот админ в группе (для закрепления) и что реакции 🟢/✖/✅ разрешены в настройках группы.

## 8. Сделать так, чтобы бот работал постоянно

Пока вы держите `python main.py` в своём терминале — бот работает только на вашем компьютере и остановится, если закрыть терминал или выключить компьютер. Для постоянной работы нужен один из вариантов:

- **Свой сервер / VPS**: запустить `main.py` как systemd-сервис (перезапускается сам при сбое и перезагрузке сервера).
- **Docker**: обернуть в контейнер, поднять на любом сервере с Docker.
- **Облачный хостинг с бесплатным тарифом** (Railway, Render, Fly.io и подобные): загрузить код, задать переменные окружения из `.env` в панели хостинга, указать команду запуска `python main.py`.

Для старта и теста достаточно шага 6 на обычном компьютере — переезд на постоянный хостинг можно сделать отдельным шагом, когда убедитесь, что логика всех устраивает.

## 9. Резервная копия

Вся история заявок хранится в одном файле `zakupki.db` (SQLite) рядом со скриптом. Периодически копируйте этот файл куда-то ещё — это единственное место, где хранятся данные.

## Настройки, которые стоит подогнать под себя

Всё в `config.py`:
- `SECTORS` / `SECTOR_PREFIX` — если появится пятый сектор или изменится название.
- `WINDOW_SUBMIT_OPEN` / `WINDOW_SUBMIT_CLOSE` / `WINDOW_REVIEW_CLOSE` / `WINDOW_PAY_CLOSE` — время окон.
- `REACTION_APPROVE` / `REACTION_REJECT` / `REACTION_PAID` — какие именно эмодзи считать статусом.

### Личный кабинет сотрудников

`/cabinet` и кнопка «Личный кабинет» открывают задачи по роли, поиск заявок и
аналитику. Администратор видит все направления. Остальные сотрудники видят
только заявки, доступные им по действующим правилам доступа к комментариям.
Бухгалтер сохраняет кнопку меню «Уведомить»; кабинет доступен через `/cabinet`
и кнопки `/start` или `/new`.

Аналитика считает только оплаченные заявки (`paid_at`, статусы оплачено / в пути /
получено), за текущую календарную неделю, месяц или год в Europe/Chisinau.
Группировки: категории, поставщики и номера заказов. Поиск и суммы применяются
до пагинации. Старые платежи без категории — «Не распределено», без номера заказа —
«Без заказа». Уведомления бухгалтера в свободной форме в расходы не входят.

Из заявки доступны формы оплаты, платёжки и комментариев по роли. Кнопка
«Открыть карточку в чате» отправляет текущую карточку только нажавшему сотруднику;
на ней работают существующие кнопки одобрения, отклонения и логистики.
Новые сообщения при просмотре кабинета автоматически не отправляются.

После «Уведомить» бухгалтер получает копию успешно отправленного директору
сообщения в свой чат. В кабинете бухгалтеру доступна собственная история
«Отправленные уведомления», включая старые записи. Если доставка копии не удалась,
повторная отправка с тем же идентификатором повторяет только недоставленную часть.
Просмотр истории ничего не отправляет; старые уведомления автоматически в чат
не дублируются.

### Исключение тестовых заявок из аналитики

Только действующий директор может нажать в карточке кабинета «Исключить из
аналитики» и подтвердить конкретную заявку. Само право администратора не даёт
этой возможности. Исключённая заявка остаётся в поиске и истории, но её сумма
не входит в аналитику и финансовые итоги поиска. Статус оплаты, файлы и
комментарии сохраняются. Действия фиксируются в журнале с автором и временем.

Директор восстанавливает заявку через «Аналитика → Исключённые заявки».
Список исключённых доступен за всё время; обычная аналитика учитывает исходную
дату оплаты после восстановления. Выкладка функции не исключает записи
автоматически. Управление правом проверяется на сервере.

### Быстродействие окон

Кабинет определяет доступ к списку заявок один раз на запрос (`access_checker`),
без кэширования ролей между запросами. Все формы используют общий загрузчик
`telegram_bootstrap.js?v=1`: интерфейс отрисовывается без ожидания внешнего SDK,
а вложенные формы используют Telegram-контекст кабинета. При изменении загрузчика
необходимо обновить параметр версии во всех формах (файл кэшируется на сутки).

Ответы веб-сервера включают `Server-Timing: app;dur=...`; запросы дольше секунды
записываются в лог с методом, путём и длительностью, без содержимого формы.
Проверка загрузчика: `node tests/test_telegram_bootstrap.cjs`.

При одобрении заявки уже раскрытый запрос платёжки у бухгалтера становится
основной карточкой оплаты. Сообщение переиспользуется отдельно для каждого
бухгалтера и снимается с учёта уведомлений, чтобы обновление платёжки не
перезаписывало кнопки основной карточки. Повторный вызов обновляет существующую
карточку; при неоднозначной сетевой ошибке новая копия не отправляется.
